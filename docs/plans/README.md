# Feature Plans

Plans describe proposed work before implementation; they are not evidence that a feature is complete.

Create a plan for substantial features, cross-cutting changes, or work with unresolved requirements. Small fixes may not need a separate plan.

## Naming

`PLAN-NNN-short-feature-name.md`

## Template

```markdown
# PLAN-NNN: Feature title

- Status: Draft | Ready for review | Approved | In progress | Implemented | Deferred
- Created: YYYY-MM-DD
- Related ADRs:
- Related features:

## Problem and motivation
## Goals
## Non-goals
## Requirements and acceptance criteria
## Current behavior
## Proposed design
## Alternatives considered
## API and data flow
## Dependencies and design patterns
## Security, privacy, and failure cases
## Testing strategy
## Documentation updates
## Implementation steps
## Risks and open questions
## Completion notes
```

For ambiguous or substantial work, clarify requirements and review the plan before coding. Update status honestly.
