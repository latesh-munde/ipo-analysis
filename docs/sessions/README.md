# Development Session Notes

Session notes preserve useful progress and context for future work. Keep them factual and concise.

## Naming

`YYYY-MM-DD-short-session-topic.md`

## Template

```markdown
# Session: Topic

- Date: YYYY-MM-DD
- Status: In progress | Completed | Blocked
- Related plan:
- Related feature:

## Objective
## Work completed
## Files changed
## Decisions made
## Tests and checks
## Findings and limitations
## Open questions / blockers
## Next steps
## Documentation updated
```

List exact commands and real outcomes for tests. Do not infer successful verification from intended behavior. Session notes do not replace current architecture or feature docs.
